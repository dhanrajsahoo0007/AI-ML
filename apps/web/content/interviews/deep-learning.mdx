Deep learning rounds check whether you understand why networks train (or fail to), not just which library calls to make. Expect questions on gradients, initialization, normalization, optimizers and the classic architectures, with follow-ups on debugging a model that will not learn.

Related reading: the [Deep learning path](/learning-paths/deep-learning), [Transformer Architecture](/ai-system-design/genai-system-design/transformer-architecture) and the [transformers & attention](/interviews/transformers-and-attention) bank.

<InterviewQuestions>
  <InterviewQuestion question="How does backpropagation work?" category="Fundamentals" level="Junior">
    After a forward pass computes the loss, backpropagation applies the chain rule from the output back to the input, computing the gradient of the loss with respect to every weight layer by layer and reusing intermediate results. An optimizer then updates the weights using those gradients. Automatic differentiation frameworks do this for any computation graph.
  </InterviewQuestion>
  <InterviewQuestion question="Why do neural networks need non-linear activation functions?" category="Fundamentals" level="Junior">
    Without non-linearities, a stack of linear layers collapses into a single linear transformation, so depth adds nothing. Non-linear activations let networks represent complex functions, and with enough units a network with one hidden layer can approximate any continuous function.
  </InterviewQuestion>
  <InterviewQuestion question="Compare sigmoid, tanh, ReLU and GELU." category="Fundamentals" level="Junior">
    Sigmoid squashes to between 0 and 1 and tanh to between minus 1 and 1; both saturate, so gradients vanish for large inputs. ReLU outputs max of zero and x, is cheap and does not saturate for positive inputs, but units can "die" if they only receive negative inputs. GELU is a smooth ReLU-like function used in transformers. Leaky ReLU and similar variants keep a small gradient for negative inputs.
  </InterviewQuestion>
  <InterviewQuestion question="What causes vanishing and exploding gradients, and how do you fix them?" category="Training" level="Mid">
    Backpropagation multiplies many per-layer derivatives; if they are mostly smaller than one, gradients shrink toward zero in early layers, and if larger than one, they blow up. Fixes include ReLU-family activations, careful initialization such as He or Xavier, normalization layers, residual connections, gradient clipping, and gated architectures like LSTMs for sequences.
  </InterviewQuestion>
  <InterviewQuestion question="Why does weight initialization matter?" category="Training" level="Mid">
    If weights are too small, signals and gradients shrink layer after layer; too large, they explode. Initializing all weights to the same value makes neurons learn identical features. Schemes such as Xavier (for tanh) and He (for ReLU) scale random initial weights to the layer size so activation variance stays roughly constant through depth.
  </InterviewQuestion>
  <InterviewQuestion question="What does batch normalization do and why does it help?" category="Training" level="Mid">
    It normalizes each feature's activations over the mini-batch to zero mean and unit variance, then applies a learned scale and shift. It allows higher learning rates, makes training less sensitive to initialization and has a mild regularizing effect. At inference it uses running averages of the statistics. It works poorly with very small batches, where layer normalization is preferred.
  </InterviewQuestion>
  <InterviewQuestion question="Batch norm vs layer norm: when do you use each?" category="Training" level="Mid">
    Batch norm normalizes across the batch for each feature, which suits CNNs with reasonable batch sizes. Layer norm normalizes across features within each example, so it does not depend on batch size or sequence length, which suits transformers, RNNs and small or variable batches.
  </InterviewQuestion>
  <InterviewQuestion question="How does dropout work and why is it turned off at inference?" category="Training" level="Junior">
    During training, dropout randomly zeroes a fraction of activations, which prevents units from co-adapting and acts like training an ensemble of sub-networks. At inference all units are used, and activations are scaled (usually during training, called inverted dropout) so expected values match. Keeping dropout on at inference would add noise to predictions.
  </InterviewQuestion>
  <InterviewQuestion question="Compare SGD with momentum and Adam." category="Optimization" level="Mid">
    SGD with momentum accumulates a moving average of gradients to smooth noisy updates and speed up along consistent directions. Adam also keeps per-parameter averages of squared gradients to adapt the step size for each parameter, so it converges quickly with less tuning. Well-tuned SGD can generalize slightly better in some vision tasks, while Adam or AdamW is the default for transformers.
  </InterviewQuestion>
  <InterviewQuestion question="What is AdamW and how does it differ from Adam with L2 regularization?" category="Optimization" level="Senior">
    In Adam, adding an L2 penalty to the loss puts it inside the adaptive gradient scaling, so parameters with large gradient history get less regularization than intended. AdamW decouples weight decay, applying it directly to the weights separately from the adaptive update, which gives more consistent regularization and better generalization. It is the standard optimizer for training transformers.
  </InterviewQuestion>
  <InterviewQuestion question="Why use learning-rate warm-up and decay schedules?" category="Optimization" level="Mid">
    Early in training, weights and optimizer statistics are poorly estimated, so large steps can destabilize the model; warm-up raises the learning rate gradually. Later, decaying the rate, for example with cosine or step schedules, lets the model settle into a good minimum instead of bouncing around it.
  </InterviewQuestion>
  <InterviewQuestion question="What is gradient clipping and when is it needed?" category="Optimization" level="Mid">
    It caps the gradient norm or values before the update so a single bad batch cannot produce a huge step. It is common for RNNs and transformers, where occasional exploding gradients can wreck training, and is cheap insurance in large-scale training.
  </InterviewQuestion>
  <InterviewQuestion question="Why do convolutional networks work well for images?" category="Architectures" level="Junior">
    Convolutions apply the same small filters across the whole image, which builds in locality and translation equivariance and drastically reduces parameters compared with fully connected layers. Stacking layers grows the receptive field, so early layers detect edges and textures and later layers detect parts and objects. Pooling or strides add some translation invariance.
  </InterviewQuestion>
  <InterviewQuestion question="How do you calculate the output size of a convolution layer?" category="Architectures" level="Junior">
    For input size W, kernel size K, padding P and stride S, the output size is (W minus K plus 2P) divided by S, plus 1, rounded down. The number of output channels equals the number of filters, and each filter has K times K times input-channel weights plus a bias.
  </InterviewQuestion>
  <InterviewQuestion question="What problem do residual connections solve in ResNet?" category="Architectures" level="Mid">
    Very deep plain networks trained worse than shallower ones, not because of overfitting but because optimization became hard. Residual connections let each block learn a correction added to its input, so an identity mapping is easy and gradients flow directly backward through the skip paths. This made networks with over a hundred layers trainable.
  </InterviewQuestion>
  <InterviewQuestion question="How do LSTMs address the problems of plain RNNs?" category="Architectures" level="Mid">
    Plain RNNs struggle to keep information over long sequences because gradients vanish through repeated multiplication. LSTMs add a cell state with input, forget and output gates that control what is written, kept and exposed, providing a path where information and gradients can flow over many steps. GRUs are a simpler gated alternative.
  </InterviewQuestion>
  <InterviewQuestion question="Why have transformers largely replaced RNNs?" category="Architectures" level="Mid">
    Transformers process all positions in parallel during training, which is far faster on modern hardware, and connect any two positions with one attention step, which handles long-range dependencies better. They also scale more predictably with data and compute. RNNs remain useful for some streaming and low-memory settings.
  </InterviewQuestion>
  <InterviewQuestion question="What is transfer learning and how do you fine-tune a pretrained model?" category="Training" level="Junior">
    Transfer learning reuses a model trained on a large dataset as the starting point for a related task. Typically you replace the output head, train it first with the backbone frozen, then unfreeze some or all layers and continue with a small learning rate. It needs far less data and compute than training from scratch.
  </InterviewQuestion>
  <InterviewQuestion question="What is an autoencoder, and what is a variational autoencoder?" category="Architectures" level="Mid">
    An autoencoder compresses input into a low-dimensional code and reconstructs it, learning useful representations for denoising, compression or anomaly detection. A variational autoencoder makes the code a probability distribution and regularizes it toward a prior, so you can sample new codes and generate new data with a smooth latent space.
  </InterviewQuestion>
  <InterviewQuestion question="How do GANs work and why are they hard to train?" category="Architectures" level="Senior">
    A generator creates samples from noise and a discriminator tries to tell them from real data; they train against each other until generated samples look real. Training is unstable because it is a two-player game: one side can overpower the other, gradients can vanish, and the generator can collapse to a few modes. Techniques such as Wasserstein losses and spectral normalization help.
  </InterviewQuestion>
  <InterviewQuestion question="How do diffusion models generate images?" category="Architectures" level="Senior">
    During training, noise is added to images over many steps, and a network learns to predict and remove the noise at each step. Generation starts from pure noise and repeatedly denoises it, optionally guided by text through conditioning such as classifier-free guidance. Latent diffusion runs this process in a compressed latent space to save compute.
  </InterviewQuestion>
  <InterviewQuestion question="What is the role of the softmax and cross-entropy loss in classification?" category="Fundamentals" level="Junior">
    Softmax turns raw scores into a probability distribution over classes. Cross-entropy measures how much probability the model assigns to the correct class, heavily penalizing confident wrong predictions. Combined, their gradient with respect to the logits is simply predicted probabilities minus the one-hot target, which makes training stable.
  </InterviewQuestion>
  <InterviewQuestion question="What is label smoothing and why use it?" category="Training" level="Senior">
    Label smoothing replaces hard one-hot targets with slightly softened ones, for example 0.9 for the true class and the rest spread across other classes. It discourages the model from becoming overconfident, improving calibration and sometimes generalization, at the cost of slightly less informative logits for tasks like distillation.
  </InterviewQuestion>
  <InterviewQuestion question="What is knowledge distillation?" category="Training" level="Mid">
    A small student model is trained to match the outputs, often the softened probability distributions, of a larger teacher model in addition to the true labels. The soft targets carry information about how classes relate, so the student learns more than from labels alone, giving a cheaper model with much of the teacher's accuracy.
  </InterviewQuestion>
  <InterviewQuestion question="Your network's training loss is not decreasing. How do you debug it?" category="Debugging" level="Mid">
    First try to overfit a tiny batch; if that fails, there is a bug. Check data and labels, input normalization, the loss function and output activation pairing, and that gradients are non-zero and finite. Then try lowering the learning rate, check initialization, and log activation and gradient statistics per layer to find dead or exploding layers.
  </InterviewQuestion>
  <InterviewQuestion question="Training accuracy is high but validation accuracy is low. What do you do?" category="Debugging" level="Junior">
    That is overfitting, or a mismatch between training and validation data. Check for leakage and distribution differences first. Then add data or augmentation, regularize with dropout and weight decay, use early stopping, reduce model size, or use a pretrained model and fine-tune it.
  </InterviewQuestion>
  <InterviewQuestion question="What is data augmentation and why does it work?" category="Training" level="Junior">
    It creates modified copies of training examples, such as crops, flips and color changes for images or back-translation and synonym swaps for text, that keep the label the same. It teaches the model invariances and effectively enlarges the dataset, reducing overfitting.
  </InterviewQuestion>
  <InterviewQuestion question="How does mixed-precision training work?" category="Training" level="Senior">
    Most computation runs in 16-bit floating point (fp16 or bf16) for speed and memory savings, while a 32-bit master copy of the weights is kept for accurate updates. With fp16, loss scaling multiplies the loss before backpropagation to stop small gradients from underflowing; bf16 has a wider range and usually does not need it.
  </InterviewQuestion>
  <InterviewQuestion question="Why are larger batch sizes not always better?" category="Optimization" level="Senior">
    Larger batches give smoother gradient estimates and better hardware use, but beyond a point they need proportionally higher learning rates and warm-up to train well, they reduce the number of updates per epoch, and very large batches can generalize worse. Memory also limits batch size; gradient accumulation simulates larger batches when needed.
  </InterviewQuestion>
  <InterviewQuestion question="How do you make a neural network smaller and faster for deployment?" category="Debugging" level="Senior">
    Quantize weights and activations to 8-bit or lower, prune unimportant weights or channels, distill into a smaller student, use efficient architectures, and compile the model with an inference runtime that fuses operations. Measure accuracy after each step, because the right combination depends on the hardware and latency target.
  </InterviewQuestion>
</InterviewQuestions>
