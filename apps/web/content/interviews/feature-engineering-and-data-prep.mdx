Good features and clean data usually matter more than model choice, and interviewers know it. Expect questions on encoding categorical variables, handling messy data, building time-aware features without leakage, and keeping training and serving features consistent.

Related: [ML fundamentals](/interviews/ml-fundamentals) · [Python & pandas](/interviews/python-and-pandas)

<InterviewQuestions>
  <InterviewQuestion question="What is feature engineering and why does it matter?" category="Fundamentals" level="Junior">
    Creating, transforming and selecting input variables so a model can learn the signal more easily, such as ratios, aggregates, time since last event or text embeddings. Well-chosen features encode domain knowledge, often improving accuracy more than switching algorithms, and can make simpler, more interpretable models viable.
  </InterviewQuestion>
  <InterviewQuestion question="One-hot encoding vs label encoding: when do you use each?" category="Encoding" level="Junior">
    One-hot creates a binary column per category and suits nominal categories with few values for linear models and neural networks. Label encoding maps categories to integers, which imposes a false order for linear models but is fine for tree-based models, which can split on arbitrary integer codes.
  </InterviewQuestion>
  <InterviewQuestion question="How do you handle high-cardinality categorical features?" category="Encoding" level="Mid">
    Options include target encoding (replacing each category with a smoothed average of the target, computed out of fold), frequency encoding, hashing into a fixed number of buckets, grouping rare categories into "other", and learned embeddings in neural networks. One-hot encoding thousands of categories creates huge sparse inputs.
  </InterviewQuestion>
  <InterviewQuestion question="What is target encoding and how do you prevent leakage with it?" category="Encoding" level="Mid">
    Each category is replaced by the mean target value for that category. Computed naively on the training set, it leaks the row's own label into its feature. Compute it out of fold, with each row's value from other folds, add smoothing toward the global mean for rare categories, and fit only on training data.
  </InterviewQuestion>
  <InterviewQuestion question="Standardization vs normalization: what is the difference?" category="Scaling" level="Junior">
    Standardization rescales to zero mean and unit variance and is the default for many linear models, SVMs and neural networks. Min-max normalization rescales to a fixed range, often 0 to 1, which is sensitive to outliers. Robust scaling with the median and interquartile range resists outliers.
  </InterviewQuestion>
  <InterviewQuestion question="When would you apply a log transform?" category="Scaling" level="Junior">
    For right-skewed positive features such as income, prices or counts, a log transform compresses large values, reduces the influence of outliers and can make relationships more linear. Use log of one plus x when zeros are present. Tree models need it less because they are invariant to monotonic transforms.
  </InterviewQuestion>
  <InterviewQuestion question="How do you create features from timestamps?" category="Time Features" level="Junior">
    Extract hour, day of week, month, holidays and weekend flags; use cyclical encoding with sine and cosine for periodic values such as hour; and compute durations such as time since signup or since the last purchase. Make sure the reference time is the prediction time, not today.
  </InterviewQuestion>
  <InterviewQuestion question="How do you build aggregate features without leakage?" category="Time Features" level="Senior">
    Compute aggregates such as "purchases in the last 30 days" using only data available before each example's prediction time, which is called point-in-time correctness. In SQL or pandas, join on time windows ending at the event timestamp. Feature stores with point-in-time joins enforce this automatically for training data.
  </InterviewQuestion>
  <InterviewQuestion question="What are lag and rolling features in time series?" category="Time Features" level="Mid">
    Lag features use the target or other variables from previous time steps, such as last week's sales. Rolling features summarize recent windows, such as a 7-day mean or standard deviation. They capture trends and seasonality, but every window must end before the time being predicted.
  </InterviewQuestion>
  <InterviewQuestion question="How do you turn text into features for a classic model?" category="Text Features" level="Junior">
    Bag of words or TF-IDF vectors with n-grams, plus simple statistics such as length, punctuation and capitalization. For richer meaning, use pretrained sentence embeddings as dense features. Clean and normalize text consistently between training and serving.
  </InterviewQuestion>
  <InterviewQuestion question="What are interaction features and when are they useful?" category="Fundamentals" level="Mid">
    Features that combine two or more variables, such as products, ratios or crosses of categories, like price per square meter or city by device. Linear models need them to capture interactions; tree models and neural networks can learn some interactions themselves but still benefit from meaningful hand-made ones.
  </InterviewQuestion>
  <InterviewQuestion question="How do you handle missing values as a feature-engineering decision?" category="Missing Data" level="Mid">
    Decide based on why data is missing. Impute with median, mode or model-based methods, add a binary "is missing" indicator because missingness can be predictive, or use models that handle missing values natively. Avoid imputing with information from the test set or future data.
  </InterviewQuestion>
  <InterviewQuestion question="What are MCAR, MAR and MNAR?" category="Missing Data" level="Senior">
    Missing completely at random means missingness is unrelated to anything, so dropping rows only loses data. Missing at random means missingness depends on observed variables, which imputation using those variables can handle. Missing not at random means it depends on the unobserved value itself, such as high earners not reporting income, which biases simple methods and needs domain modeling.
  </InterviewQuestion>
  <InterviewQuestion question="How do you treat outliers before modeling?" category="Data Quality" level="Junior">
    Investigate first: fix or remove data errors, keep genuine extreme values if they matter. To reduce their influence, cap or winsorize, transform with logs, use robust scalers and losses, or choose models less sensitive to them, such as trees.
  </InterviewQuestion>
  <InterviewQuestion question="What is feature selection, and what methods exist?" category="Selection" level="Mid">
    Choosing a subset of features to reduce overfitting, cost and complexity. Filter methods rank features by statistics such as correlation or mutual information; wrapper methods search subsets using model performance, such as recursive feature elimination; embedded methods select during training, such as L1 regularization or tree importances.
  </InterviewQuestion>
  <InterviewQuestion question="How do you handle highly correlated features?" category="Selection" level="Mid">
    They can make linear model coefficients unstable and split importance between them. Drop one of each highly correlated pair, combine them, use PCA, or rely on regularization such as ridge. For pure prediction with trees, correlation matters less, but interpretation still suffers.
  </InterviewQuestion>
  <InterviewQuestion question="What is training-serving skew?" category="Production" level="Senior">
    A difference between how features are computed for training and for live predictions, such as different code paths, time zones, default values or data freshness. Models then see different inputs in production than they learned from and degrade silently. Prevent it by sharing feature code, using a feature store, logging served features and comparing distributions.
  </InterviewQuestion>
  <InterviewQuestion question="What is a feature store?" category="Production" level="Senior">
    A system that manages feature definitions and values for both training and serving: an offline store with history for building point-in-time-correct training sets, and an online low-latency store for live inference, both fed by the same transformation logic. It reduces duplication, skew and leakage and lets teams reuse features.
  </InterviewQuestion>
  <InterviewQuestion question="How do you validate data quality in a pipeline?" category="Data Quality" level="Mid">
    Define expectations and check them automatically on every run: schema and types, null rates, value ranges, uniqueness of keys, allowed categories, row counts and freshness, and distribution shifts compared with past runs. Fail or alert on violations before bad data reaches models or dashboards.
  </InterviewQuestion>
  <InterviewQuestion question="How should you split data for time-dependent problems?" category="Fundamentals" level="Mid">
    Split by time: train on the past, validate and test on later periods, mirroring how the model will be used. Random splits leak future patterns into training and overstate performance. For cross-validation, use expanding or rolling windows.
  </InterviewQuestion>
  <InterviewQuestion question="How do you engineer features for a fraud detection model?" category="Case" level="Senior">
    Combine transaction attributes such as amount, merchant category and channel; velocity features such as transactions per card in the last hour or day; deviations from the user's normal behavior such as distance from usual location or amount versus average; device and network signals; and graph features linking cards, devices and accounts. All must be computable in real time at prediction.
  </InterviewQuestion>
  <InterviewQuestion question="How do you engineer features for churn prediction?" category="Case" level="Mid">
    Recency, frequency and monetary features, trends in usage such as activity this month versus last, engagement depth with key features, support tickets and complaints, plan and tenure, payment failures, and seasonality. Define the prediction point and churn window clearly so features only use data before the prediction point.
  </InterviewQuestion>
  <InterviewQuestion question="What is data augmentation for tabular data, and does it help?" category="Fundamentals" level="Senior">
    Generating synthetic rows, for example with SMOTE for minority classes, noise injection, or generative models. It can help imbalanced or small datasets, but synthetic rows can blur class boundaries or create unrealistic combinations, so validate on real data only and prefer simpler fixes such as class weights first.
  </InterviewQuestion>
  <InterviewQuestion question="Embeddings vs hand-crafted features: when do you use each?" category="Fundamentals" level="Mid">
    Learned embeddings capture complex patterns in unstructured data such as text, images and user-item interactions, and work well with large data. Hand-crafted features encode domain knowledge directly, are interpretable and data-efficient. Strong systems often combine both, feeding embeddings and engineered features into the same model.
  </InterviewQuestion>
  <InterviewQuestion question="How do you check whether a new feature actually helps?" category="Selection" level="Mid">
    Compare validation performance with and without it using the same splits and several seeds, check that the gain is consistent across segments and time periods, verify it cannot leak the target, and confirm it is available at serving time with the same definition. Finally, confirm the improvement online if it matters.
  </InterviewQuestion>
  <InterviewQuestion question="How do you handle categories that appear in production but not in training?" category="Encoding" level="Mid">
    Reserve an "unknown" bucket during training, for example by mapping rare categories to it, so the model has learned something for unseen values. Hashing encoders naturally handle new values. Monitor the rate of unseen categories, since a spike can signal upstream changes.
  </InterviewQuestion>
  <InterviewQuestion question="What is binning, and when is it useful?" category="Scaling" level="Junior">
    Grouping a continuous variable into intervals, such as age bands. It can capture non-linear effects in linear models, reduce noise and make features interpretable, but it loses information within bins and the choice of boundaries matters. Trees effectively learn their own bins.
  </InterviewQuestion>
  <InterviewQuestion question="How do you deal with label noise in your data?" category="Data Quality" level="Senior">
    Estimate it by auditing samples and measuring annotator agreement, then improve labeling guidelines, use multiple annotators with adjudication, and find likely mislabeled examples with confident-learning methods or high-loss examples. Robust losses and regularization reduce its impact during training.
  </InterviewQuestion>
  <InterviewQuestion question="How do you document features so others can trust and reuse them?" category="Production" level="Mid">
    Record each feature's definition, source tables, computation logic and time window, owner, freshness, known caveats and the models that use it, ideally in a feature store or catalog. Version definitions, because changing a feature silently changes every model that depends on it.
  </InterviewQuestion>
  <InterviewQuestion question="How do you encode geographic data such as latitude and longitude?" category="Encoding" level="Mid">
    Raw coordinates work for tree models, but more useful features include distance to key points such as stores or the user's home, clustering locations into regions, geohash or grid-cell ids, and joining area-level statistics such as population density. Use haversine distance for accuracy over large areas.
  </InterviewQuestion>
</InterviewQuestions>
