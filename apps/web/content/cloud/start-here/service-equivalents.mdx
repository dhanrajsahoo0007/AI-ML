Most cloud services exist on all three providers under different names. Some are near-identical (managed Kubernetes, object storage); some differ in ways that change a design (a global VPC on Google Cloud, no ECS-style orchestrator outside AWS). This map lists each **capability**, meaning a job you need done, with the service that does it on each cloud and how close the match is.

## How to read it

- **Search** by the job ("queue", "CDN") or by a service you already know ("Fargate", "Spanner", "Cosmos") to find its counterparts.
- **List first** puts the cloud you know in the first, tinted column.
- **The dot** shows how well each cloud covers the job. *Direct* means a first-class service built for it. *Close* means it does the job with a different model you should mention in an interview. *Partial* means a workaround or a narrower feature. *No equivalent* means you would build it or buy it from a partner.
- **Notes** call out the differences that change a design, plus retirements and renames as of the date at the bottom.

## Differences that change a design

| Topic | AWS | Google Cloud | Azure |
|---|---|---|---|
| **Network scope** | VPC per Region | One VPC spans all Regions | VNet per Region |
| **Serverless containers** | Fargate, under ECS or EKS | Cloud Run, standalone | Container Apps, standalone |
| **Global HTTP entry** | CloudFront or Global Accelerator in front of Regional load balancers | Global external load balancer with one anycast IP | Front Door |
| **Distributed SQL** | Aurora DSQL (2025) | Spanner (since 2017) | No direct equivalent |
| **Event streaming** | Kinesis or MSK: partitions and offsets | Pub/Sub: ordering keys, seek by time | Event Hubs: partitions and offsets, Kafka endpoint |
| **Organisation model** | Accounts in an Organization | Projects in folders in an organization | Subscriptions and resource groups under management groups |
