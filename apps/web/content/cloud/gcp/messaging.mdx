Google Cloud has one product where AWS has three: **Pub/Sub** acts as a queue, a fan-out topic and an event stream, with no partitions or shards to manage. **Cloud Tasks** adds rate-limited HTTP task queues, and **Managed Service for Apache Kafka** covers Kafka workloads.

## TL;DR

- **Pub/Sub** for queues (pull subscriptions), fan-out (many subscriptions) and streams (ordering keys, seek to replay).
- **Ordering is per ordering key** and enabled per subscription; delivery is at least once, exactly-once optional on pull.
- **Cloud Tasks** to call HTTP handlers at a controlled rate with retries.
- **Managed Kafka** when you need the Kafka API and ecosystem.

## Coming from AWS

| On AWS | On Google Cloud | What actually changes |
|---|---|---|
| SQS | Pub/Sub pull subscription or Cloud Tasks | Ack deadlines instead of visibility timeouts |
| SNS → SQS fan-out | One topic, many subscriptions | No extra queue per subscriber; each subscription keeps its own backlog |
| Kinesis | Pub/Sub | No shards; ordering keys and seek instead of partitions and offsets |
| MSK | Managed Service for Apache Kafka | Sized by vCPU and memory |
| Firehose | BigQuery and Cloud Storage subscriptions | Pub/Sub writes straight to the destination |
