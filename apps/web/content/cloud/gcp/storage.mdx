**Cloud Storage** is Google Cloud's object store. Its location model is the main difference from S3: a bucket can be **regional, dual-region or multi-region**, and the multi-location types replicate across Regions automatically. Block storage (**Persistent Disk** and **Hyperdisk**) and file storage (**Filestore**, **Managed Lustre**, **NetApp Volumes**) fill the same roles as EBS, EFS and FSx.

## TL;DR

- **Cloud Storage** for blobs; pick **dual- or multi-region** buckets for built-in cross-Region durability.
- **Autoclass** moves objects between Standard, Nearline, Coldline and Archive automatically.
- **Hyperdisk** for high-performance VM disks; **regional persistent disks** replicate across two zones.
- **Filestore** for shared NFS; **Managed Lustre** for ML and HPC throughput.

## Coming from AWS

| On AWS | On Google Cloud | What actually changes |
|---|---|---|
| S3 + Cross-Region Replication | Dual- or multi-region bucket | Cross-Region copies with no replication rules |
| S3 Intelligent-Tiering | Autoclass | Per-bucket automatic class changes |
| EBS (zonal) | Persistent Disk / Hyperdisk, regional option | Synchronous two-zone replication is available |
| EFS | Filestore | Provisioned capacity by tier instead of pay-per-use elastic |
| Pre-signed URL | Signed URL | Same pattern for direct uploads |
