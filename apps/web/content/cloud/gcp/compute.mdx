Google Cloud's VM service, **Compute Engine**, works much like EC2. The differences that matter in a design are smaller conveniences: custom machine shapes, live migration during host maintenance, **regional managed instance groups** that spread VMs across zones in one resource, and automatic sustained-use discounts on some machine families. For new stateless services, Google's own default is **Cloud Run**, not VMs.

## TL;DR

- **Compute Engine** when you need the machine: GPUs or TPUs, licensed software, steady high load.
- **Regional managed instance groups** autoscale and auto-heal VMs across zones, behind the global load balancer.
- **Spot VMs** for interruptible work (about 30 seconds of notice); **committed use discounts** for steady load.
- **Batch** for queued jobs; **App Engine** mostly for existing apps, since Cloud Run is the default for new ones.

## Coming from AWS

| On AWS | On Google Cloud | What actually changes |
|---|---|---|
| EC2 | Compute Engine | Custom machine shapes; live migration for maintenance |
| Auto Scaling group | Managed instance group (regional) | One regional MIG spans zones; autoscaling and auto-healing are built in |
| Spot (2-minute notice) | Spot VMs (about 30 seconds) | Shut down faster; save state more often |
| Savings Plans | Committed use discounts | Some machine families also get automatic sustained-use discounts |
| Graviton | Axion (C4A), Tau T2A | Same arm64 build caveats |
