Brightpost uses AI in three places. A drafter writes replies to about 60 support emails a day, a support chatbot answers customers, and a tagger labels product photos with style words. On Google Cloud nearly all of it sits in one platform, **Vertex AI**: Gemini and partner models, retrieval, evaluation, and training for the one model Brightpost owns. One more door matters here. **BigQuery ML** trains simple models with SQL inside the warehouse, so a data team can forecast without leaving its tables.

## The idea

Clouds sell AI as a ladder, from a finished service you call to a model you train and run yourself. Use the lowest rung that passes your tests: keep facts that change in a search index, and own a model only where nothing hosted does the job.

## TL;DR

- **Vertex AI** serves Gemini, plus partner and open models through **Model Garden**, paid per token or by Provisioned Throughput.
- **Vertex AI RAG Engine** and **Vector Search** ground answers in your documents; **Agent Engine** runs agents in production.
- **BigQuery ML** trains and runs forecasts and classifiers with SQL, where the data already is.
- **Model Armor** screens prompts and replies for any model. **TPUs** are Google's own chips for large training jobs.

## How it fits together on Google Cloud

In steps 1 and 2 Asha's tuned model ran on its own GPU machine, billed every hour. It never saw the edited help article, so drafts kept the old Christmas date. Step 3 deletes that endpoint, and the drafter calls Gemini on Vertex AI, paid per token.

In step 4 the help articles sit in Cloud Storage. A RAG Engine import splits and embeds them into a vector store, such as Vector Search, and a Cloud Storage event starts the import on each edit. Step 5 runs Brightpost's 80 test questions through the Gen AI evaluation service before any change ships.

Step 6 differs most here. Gemini can be called through a regional endpoint or a global one, and the global one may serve the request from any region. Brightpost uses a regional endpoint in a region its data rules allow, reached through Private Service Connect, and Cloud Monitoring counts the tokens. Step 7 trains the photo style tagger with Vertex AI Pipelines and keeps approved versions in the Model Registry.

| The idea | On Google Cloud | What to know |
|---|---|---|
| Hosted model catalog | Model Garden in Vertex AI | Gemini is Google's own; partner models such as Claude have their own terms and regions |
| Managed retrieval | Vertex AI RAG Engine; Vertex AI Search | RAG Engine gives you the parts; Vertex AI Search is a finished search product |
| Where a call is processed | Regional or global endpoint | Pick the regional endpoint when data must stay in one region |
| Guardrail | Model Armor | Floor settings set the minimum filters for a project, folder or organisation |
| Machine learning in SQL | BigQuery ML | `CREATE MODEL` and `ML.FORECAST` run inside the warehouse |

## Machine learning in SQL: BigQuery ML

The finance lead wants next week's orders, from two years of daily totals already in BigQuery. A time-series model trains with one statement and forecasts with another. No data moves, and no endpoint waits all day.

```sql
CREATE OR REPLACE MODEL shop.orders_forecast
OPTIONS (model_type = 'ARIMA_PLUS',
         time_series_timestamp_col = 'day',
         time_series_data_col = 'orders') AS
SELECT day, orders FROM shop.daily_orders;

SELECT * FROM ML.FORECAST(MODEL shop.orders_forecast, STRUCT(7 AS horizon));
```

It suits tables: forecasts, churn scores, simple classifiers. BigQuery can also call a Gemini model from SQL through a remote model, for example to tag the mood of support emails in a query. It is not for chat or retrieval. The warehouse itself is on [Analytics & Data on Google Cloud](/cloud/gcp/analytics).

## Services

### Vertex AI

<CloudServiceProfile id="gcp-vertex-ai" />

**Pick it when** a feature needs a foundation model, or you train and serve your own. It is the default for both on Google Cloud.

### Vertex AI Agent Engine

<CloudServiceProfile id="gcp-agent-engine" />

**Pick it when** an agent calls tools for many users and needs sessions, memory and tracing you would otherwise build.

### Model Armor

<CloudServiceProfile id="gcp-model-armor" />

**Pick it when** any model, Gemini or not, takes text from customers or retrieved documents. It is a filter, so keep the tools scoped and refunds over £30 waiting for a person.

### Cloud TPU

<CloudServiceProfile id="gcp-tpu" />

**Pick it when** you train or serve large models in JAX or PyTorch/XLA and TPUs beat GPUs on price for that job. Brightpost's tagger is too small to need them.

The ready-made APIs have no profiles here: Cloud Vision, Speech-to-Text, Cloud Translation, Natural Language and Document AI each do one job, paid per item.

## Common mistakes

- **Calling the global endpoint with customer data.** It may process the prompt in any region. Use a regional endpoint where data rules apply.
- **Expecting RAG Engine to watch the bucket.** An import runs when something starts it. Trigger it on each edit, or the index keeps old facts.
- **Exporting warehouse tables to train a forecast.** BigQuery ML trains where the data already is. Reach for Vertex AI only when SQL models fall short.

  <InterviewQuestion question="When would a data team use BigQuery ML instead of Vertex AI?" category="Cloud" level="Junior">
    **Short answer.** When the data is already in BigQuery tables and the model is a standard kind, such as a forecast, a classifier or a regression. One SQL statement trains it and another scores rows. Vertex AI is for custom training code, images, text models and online serving.

    **Why.** Brightpost's finance lead forecasts next week's orders from two years of daily totals. With BigQuery ML that is a `CREATE MODEL` and an `ML.FORECAST` query, with no data export and nothing left running. The photo style tagger needs custom training on images, so it lives in Vertex AI.

    **Follow-ups the interviewer may ask.**
    - How would you check the forecast is any good before the team relies on it?
    - Can a BigQuery ML model be served outside BigQuery?

    **Watch out for.** Saying SQL models are toys. For tabular forecasts they are often enough, and the data never leaves the warehouse.
  </InterviewQuestion>

  <InterviewQuestion question="How does an edited help article reach the next answer when Brightpost uses Vertex AI RAG Engine?" category="Cloud" level="Mid">
    **Short answer.** The articles live in Cloud Storage. An import into RAG Engine splits and embeds them into the vector store. A Cloud Storage event starts the import when an article changes, so the next search finds the new text.

    **Why.** A tuned model learned the Christmas date from 9,000 old emails and kept it after the article changed: 70 wrong drafts and 23 refunds. With retrieval, the edit is in the index about 5 minutes later. The drafter asks for the 3 closest passages and sends them to Gemini with the question. Nothing is retrained.

    **Follow-ups the interviewer may ask.**
    - What happens to the vectors of a deleted article?
    - When would you choose Vertex AI Search over RAG Engine?

    **Watch out for.** A nightly import. The date would still be wrong for up to a day, which is a day of wrong drafts.
  </InterviewQuestion>

  <InterviewQuestion question="Where does Model Armor sit in Brightpost's support chatbot, and what does it not stop?" category="Cloud" level="Mid">
    **Short answer.** It checks each prompt before Gemini reads it and each reply before the customer sees it, for injection attempts, harmful content and personal data. It does not stop a tricked model from using a tool that can do too much.

    **Why.** A pasted note once refunded a stranger's order. Model Armor would catch many such notes, but filters miss new tricks. So the tools run under a service account scoped to the signed-in customer, and Workflows holds any refund over £30 for the support agent. Floor settings make sure no team ships a bot without the checks.

    **Follow-ups the interviewer may ask.**
    - Should retrieved documents pass Model Armor as well as the customer's message?
    - What does the chatbot tell a customer whose prompt was blocked?

    **Watch out for.** Calling Model Armor the security design. It is a smoke alarm; scoped tools and a person for big refunds are the locks.
