On Google Cloud, serverless means **Cloud Run**. Functions (Cloud Run functions, formerly Cloud Functions) run on it, events reach it through **Eventarc** or **Pub/Sub**, **Workflows** coordinates multi-step processes, and **API Gateway** or **Apigee** sits in front. Because a Cloud Run instance serves many requests at once, serverless designs here hit fewer cold starts and database-connection limits than on Lambda.

## TL;DR

- **Cloud Run functions** for event-driven glue; **Cloud Run services** for anything longer-lived.
- **Workflows** for multi-step processes and sagas, defined in YAML or JSON.
- **Eventarc** routes Google Cloud and custom events; **Pub/Sub** carries high-volume events.
- **API Gateway** for simple serverless APIs; **Apigee** for full API management.

## Coming from AWS

| On AWS | On Google Cloud | What actually changes |
|---|---|---|
| Lambda | Cloud Run functions | Many requests per instance, so fewer cold starts and connections |
| Step Functions | Workflows | YAML/JSON definitions; no visual designer as the main authoring tool |
| EventBridge | Eventarc | Built on Pub/Sub; Advanced tier adds buses and pipelines |
| API Gateway WebSocket APIs | Cloud Run with WebSockets | No managed connection service; you hold connections in Cloud Run |
| EventBridge Scheduler | Cloud Scheduler | Cron jobs that call HTTP, Pub/Sub or Workflows |
