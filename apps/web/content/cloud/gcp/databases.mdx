Google Cloud's database line-up is smaller than AWS's but includes two systems other clouds copied: **Spanner**, the first globally distributed, strongly consistent SQL database, and **Bigtable**, the wide-column store behind many Google products. **Cloud SQL** and **AlloyDB** cover PostgreSQL and MySQL, and **Firestore** covers serverless documents.

## TL;DR

- **Cloud SQL** by default for relational data; **AlloyDB** for demanding PostgreSQL and mixed analytics.
- **Spanner** when relational data outgrows one primary or must survive a Region failure with strong consistency.
- **Firestore** for serverless app data with real-time listeners; **Bigtable** for huge write-heavy tables.
- Search has no first-party OpenSearch equivalent: use Vertex AI Search, AlloyDB/Spanner full-text, or Elastic via Marketplace.

Spanner shards data automatically by primary key range and commits transactions across shards using synchronised clocks (TrueTime). The design rule that matters most is the key: a timestamp or auto-increment key sends every new write to the same shard.

## Coming from AWS

| On AWS | On Google Cloud | What actually changes |
|---|---|---|
| RDS | Cloud SQL | Similar; Enterprise Plus edition adds faster failover |
| Aurora PostgreSQL | AlloyDB | Adds a columnar engine for analytical queries |
| Aurora DSQL | Spanner | Spanner is older, sized by compute, with interleaved tables and graph support |
| DynamoDB | Firestore or Bigtable | Firestore for app data, Bigtable for very high write rates; neither is a drop-in |
| OpenSearch Service | Vertex AI Search or Marketplace Elastic | No managed OpenSearch from Google |

  <InterviewQuestion question="Why do sequential primary keys hurt in Spanner and Bigtable?" category="Data modeling" level="Senior">
    Both store rows sorted by key and split the key space into ranges served by different servers. Sequential keys send every new write to the last range, creating a hotspot on one server. Use UUIDs, bit-reversed sequences, or a hashed prefix so writes spread across ranges.
