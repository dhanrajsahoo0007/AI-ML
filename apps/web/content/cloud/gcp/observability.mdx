Google Cloud Observability groups **Cloud Monitoring** (metrics, uptime checks, SLOs, alerting), **Cloud Logging** (logs, log-based metrics, sinks) and **Cloud Trace**. **Managed Service for Prometheus** stores Prometheus metrics in the same backend, and **Cloud Audit Logs** record who changed what.

## TL;DR

- **SLOs in Cloud Monitoring** with burn-rate alerts on the user-facing signals.
- **Cloud Logging** with exclusion filters and sinks to BigQuery for analysis.
- **OpenTelemetry** into Cloud Trace for distributed traces.
- **Audit Logs** are on for admin activity by default; enable data access logs where needed.

## Coming from AWS

| On AWS | On Google Cloud | What actually changes |
|---|---|---|
| CloudWatch metrics and alarms | Cloud Monitoring | Built-in SLO objects and burn-rate alerts |
| CloudWatch Logs | Cloud Logging | Sinks route logs to BigQuery, Storage or Pub/Sub |
| X-Ray | Cloud Trace | Both use OpenTelemetry |
| CloudTrail | Cloud Audit Logs | Admin activity logs are always on |
