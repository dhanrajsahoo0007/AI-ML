The biggest networking difference between the clouds is on Google Cloud: a **VPC is global**. One network spans every Region, subnets are regional, and VMs in different Regions talk privately with no peering or transit hub. Combined with the **global external load balancer**, a multi-Region design on Google Cloud needs noticeably less plumbing than on AWS.

## TL;DR

- **One global VPC** per environment; **Shared VPC** lets many projects use a centrally managed network.
- **Firewall rules and policies** target network tags or service accounts.
- **Cloud NAT** for outbound internet from private VMs; **Private Service Connect** for private access to services.
- **Cloud Load Balancing**: one global anycast IP for HTTP across Regions, plus regional and internal options.

## Coming from AWS

| On AWS | On Google Cloud | What actually changes |
|---|---|---|
| VPC per Region + Transit Gateway | One global VPC | Cross-Region private traffic needs no peering or hub |
| Security groups | Firewall rules by tag or service account | Rules live on the network and target workloads by identity |
| NAT gateway per zone | Cloud NAT | Software-defined, no gateway instances, regional |
| ALB + CloudFront/Global Accelerator | Global external Application Load Balancer | One anycast IP fronts backends in many Regions |
| PrivateLink | Private Service Connect | Same idea, also used to reach managed services like Cloud SQL |
