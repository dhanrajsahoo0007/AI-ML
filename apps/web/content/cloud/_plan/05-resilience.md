This hub is for a reader who can already draw a three-tier app in a cloud region (Fundamentals, Networking, Compute, Data) and now has to promise something about it: "it stays up", "it survives losing a region", "the data is encrypted", "an auditor can check". Read it in order: first the four pages on staying up (availability math, HA, DR, backups), then the two on going global and surviving limits, then the two on protecting data (encryption, secrets), then the four on protecting the system (zero trust, detection, compliance, AI security). Brightpost runs through every page: it starts as one VM in one zone and ends as an audited, multi-region shop with an AI support agent behind guardrails. Database-family theory (replication modes, quorums, conflict resolution) is linked to /system-design/databases, never re-taught.
