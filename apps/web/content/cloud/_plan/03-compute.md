For anyone who has heard "just put it on a VM", "containerise it" or "make it serverless" and wants to know what those words buy and cost. Read in order: the spectrum first (one picture that the rest of the hub fills in), then VMs and autoscaling (the base everything else is built on), then containers and Kubernetes, then the two serverless pages, then batch/GPUs, and finish with the decision page, which is `start-here/choosing-compute` (the hub page links to it; this hub has 8 pages). Brightpost, the running shop, starts on one VM on page 2 and ends with recommendation GPUs on page 8.

#### 4. containers-and-registries — Containers and Registries (Beginner, ~1,600 words)

The page explains why this makes "works on my machine" go away and what a registry adds (tags, digests, scanning, replication, pull cost).
- Sections: The problem: Brightpost's three servers drift apart · What a container is (process, namespace, limits) and what it is not (a VM) · Images and layers · Tags vs digests: why "latest" lies · Registries: push, scan, pull, replicate · The pull path and why it slows scale-out · What breaks: a vulnerable base layer everywhere · Try it · On AWS / Google Cloud / Azure · Common mistakes · Related · Interview questions
- Diagrams:
