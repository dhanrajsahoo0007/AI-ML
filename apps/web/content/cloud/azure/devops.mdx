On Azure, infrastructure as code is **Bicep** (which compiles to ARM templates) or Terraform. Pipelines run in **Azure Pipelines** or, increasingly, **GitHub Actions** with OIDC federation to Entra ID. **App Configuration** provides feature flags and central settings.

## TL;DR

- **Bicep** (or Terraform) for every resource, deployed with **deployment stacks** to manage them as a unit.
- **GitHub Actions or Azure Pipelines** with workload identity federation; no stored service principal secrets.
- **Deployment slots** (App Service) or **revisions** (Container Apps) for safe rollouts.
- **App Configuration** for feature flags and settings, with Key Vault references for secrets.

## Coming from AWS

| On AWS | On Azure | What actually changes |
|---|---|---|
| CloudFormation / CDK | Bicep / ARM | Day-one support for new Azure resource types |
| CodePipeline | Azure Pipelines / GitHub Actions | GitHub is Microsoft's strategic CI/CD |
| AppConfig | App Configuration | Feature flags with targeting filters |
| Systems Manager | Azure Update Manager + Azure Arc | Also manages servers outside Azure |
