Identity is Azure's home ground. **Microsoft Entra ID** handles employee sign-in and access to Azure, **managed identities** let services authenticate without secrets, **Azure RBAC** and **Azure Policy** control and constrain what can be done, and **Entra External ID** covers customer sign-in. **Key Vault**, **WAF**, **DDoS Protection** and **Defender for Cloud** complete the picture.

## TL;DR

- **Managed identities** for every app, with Azure RBAC roles; no connection strings with keys.
- **Azure Policy** as guardrails across subscriptions (allowed Regions, required encryption, no public IPs).
- **Key Vault** for secrets, keys and certificates, behind private endpoints.
- **Front Door WAF** at the edge; **Defender for Cloud** for posture and threats.

## Coming from AWS

| On AWS | On Azure | What actually changes |
|---|---|---|
| IAM role for a workload | Managed identity + Azure RBAC | Assigned to the resource; tokens come from Entra ID |
| SCPs / AWS Config rules | Azure Policy | Deny or audit non-compliant resources at any scope |
| Cognito | Entra External ID | Azure AD B2C is closed to new customers |
| KMS + Secrets Manager + ACM | Key Vault | One service for keys, secrets and certificates |
| Security Hub + GuardDuty | Defender for Cloud | Also covers AWS and Google Cloud accounts |
