Azure groups blob, file, queue and table storage under a **storage account**, and **redundancy is chosen per account**: locally (LRS), across zones (ZRS), to a paired Region (GRS) or both (GZRS). **Blob Storage** has hot, cool, cold and archive tiers, and turning on the **hierarchical namespace** makes it Data Lake Storage for analytics.

## TL;DR

- **Blob Storage** for blobs; choose **ZRS** or **GZRS** for zone or Region resilience.
- **Lifecycle policies** move blobs from hot to cool, cold and archive.
- **Managed Disks** (Premium SSD v2, Ultra) for VMs; **Azure Files** for SMB/NFS shares.
- **SAS tokens** give clients direct, time-limited access.

## Coming from AWS

| On AWS | On Azure | What actually changes |
|---|---|---|
| S3 bucket | Storage account + container | Redundancy and some limits are set per account |
| S3 Cross-Region Replication | GRS / GZRS | Replication to the paired Region is an account setting |
| Pre-signed URL | Shared access signature (SAS) | Prefer user-delegation SAS signed with Entra ID |
| EFS / FSx for Windows | Azure Files | SMB and NFS in one service |
| EBS gp3 / io2 | Premium SSD v2 / Ultra Disk | Performance set independently of size |
