Azure splits messaging by job. **Service Bus** is the enterprise broker for queues and topics, with sessions, transactions and duplicate detection. **Event Hubs** is the partitioned event stream, with a Kafka-compatible endpoint. **Event Grid** routes discrete events. **Queue Storage** is a cheap, simple queue inside a storage account.

## TL;DR

- **Service Bus queues** for work; **Service Bus topics** for fan-out with per-subscription filters.
- **Sessions** give ordered, one-at-a-time processing per key.
- **Event Hubs** for telemetry and clickstreams, readable with Kafka clients; **Capture** writes to storage.
- **Event Grid** for reacting to resource events and routing domain events.

## Coming from AWS

| On AWS | On Azure | What actually changes |
|---|---|---|
| SQS FIFO | Service Bus sessions | Plus transactions and scheduled messages |
| SNS → SQS | Service Bus topic with subscriptions | Each subscription is its own durable queue with SQL-like filters |
| Kinesis / MSK | Event Hubs | Partitions and consumer groups; Kafka endpoint instead of real brokers |
| Firehose | Event Hubs Capture | Writes Avro or Parquet to Blob or Data Lake Storage |
| Amazon MQ | Service Bus Premium | AMQP 1.0 and JMS 2.0 |
