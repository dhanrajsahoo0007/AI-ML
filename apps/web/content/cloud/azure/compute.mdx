Azure's VM service is **Virtual Machines**, with **Virtual Machine Scale Sets** for autoscaling fleets. The Azure-specific strengths are Windows and SQL Server licensing (**Azure Hybrid Benefit** reuses existing licences) and **App Service**, the most widely used code-to-web-app platform of the three clouds. For new event-driven or containerised services, **Container Apps** and **Functions** usually come first.

## TL;DR

- **Virtual Machines + Scale Sets** across availability zones when you need the machine.
- **Reservations** or the **savings plan for compute** for steady load; **Spot VMs** for interruptible work (about 30 seconds of notice).
- **App Service** for classic web apps and APIs, with deployment slots for zero-downtime swaps.
- **Azure Batch** for large parallel jobs.

## Coming from AWS

| On AWS | On Azure | What actually changes |
|---|---|---|
| EC2 + Auto Scaling group | Virtual Machines + Scale Sets | Flexible orchestration mixes VM sizes and Spot |
| Savings Plans | Savings plan for compute, Reservations | Hybrid Benefit cuts Windows and SQL Server costs further |
| Elastic Beanstalk | App Service | Deployment slots, built-in auth, more widely used |
| Graviton | Cobalt 100 | Arm-based VMs; same arm64 caveats |
