Given a positive integer amount and a list of coin/note denominations, compute how many of each
denomination to use so the total equals amount using the minimum number of pieces. Denominations
are such that taking the largest feasible denomination at each step is optimal (canonical system).

## Examples

````text
Example 1:
    Input: amount = 655, denominations = [5, 10, 20, 100, 200]
    Output: {200: 3, 20: 2, 10: 1, 5: 1}  (total 7 notes)

Example 2:
    Input: amount = 30, denominations = [5, 10, 25]
    Output: {25: 1, 5: 1}

Example 3:
    Input: amount = 7, denominations = [2, 4]
    Output: {}  (impossible when greedy leaves remainder)
````

## Constraints

````text
- Denominations are positive integers
- amount >= 0
````

## Approach

**Pattern:** Greedy Change Making
Process denominations from largest to smallest, taking as many of each as fits.

1. Sort denominations descending without mutating the caller's list.
2. For each denomination, take floor(amount / d) pieces and reduce the remainder.
3. If remainder is zero, return a dict of denomination to count; otherwise return an empty dict meaning impossible under this greedy.

## Complexity

**Time:** O(m log m + m) for m denominations (sort + scan).

**Space:** O(m) for the sorted copy and result mapping.

## Solution

````python
from typing import Dict, List


class Solution:
    def getUsedNotes(self, amount: int, denominations: List[int]) -> Dict[int, int]:
        if amount == 0:
            return {}
        used: Dict[int, int] = {}
        remaining = amount
        # Always grab the largest note that still fits — classic cashier's algorithm.
        for note in sorted(denominations, reverse=True):
            if remaining >= note:
                count = remaining // note
                used[note] = count
                remaining -= count * note
        if remaining != 0:
            # Under arbitrary denominations greedy can leave a positive remainder; signal failure.
            return {}
        return used
````
